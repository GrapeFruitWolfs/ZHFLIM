# 婚礼交付：作品、用心与珍藏

2026-09-28 · 设计讨论稿，尚未作为产品规格冻结。

## 已查看的参考

用户提供的网盘目录中有两份 Canva PDF：两页的《婚礼影像交付回执 & 制作说明（模板）》与六页的实际案例。已读取两份文档，并查看实际案例全部六页的图像。样本包含交付清单、LOG 工作流、肤色精修、音频优化、制作软件截图、三组前后画面、观看保存建议和修改约定。

原稿的价值在于清楚交代了制作工作和服务边界。排版改进空间包括：A4 三列表格在手机上缩小、技术截图占较多篇幅、正文与截图的关系不够紧密、部分前后对比跨页，以及第五页末尾“修改后”标签与下一页图片分离。

原稿已标注的 Before／After 次序按原文保留；制作截图不等同于可单独下载的交付素材。第三组的前后图存在人物动作差异，正式用作严格调色对照时应优先提供同一时刻、同一裁切的画面。

## 产品表达

建议把主体验定位为“给新人的私人影像交付”。客户依次理解：

1. 这是属于我们的作品。
2. 这次收到了哪些内容，怎样获取。
3. 摄影师在哪些地方投入了心思。
4. 怎样观看、保存和反馈。

Apple 风格可借鉴的具体方法是明确的视觉主次、大幅真实图片、克制的色彩、易读的文字和连贯的操作。婚礼照片和中文内容形成自己的风格，不使用 Apple 标识或产品外观。

## 推荐主方向：安静的影像展册

- 白色／近白色为主画布，深灰正文，少量低饱和强调色。色彩丰富的婚礼照片承担视觉焦点。
- 封面优先展示真实成片、新人身份和日期；中文主标题传递情绪，英文作为小范围的辅助标识。
- 大标题与正文形成明确级差，但一屏保留足够内容。留白用于划分关系，不固定为每个短段落占满一页。
- 正文以手机实际显示约 16px 为起点，行高约 1.7–1.85；关键标签约 12–14px。需要按 PDF 缩放后的实际阅读宽度验收。
- 图片默认保留完整构图。封面需要裁切时单独设置并确认；Before／After 必须保持一致裁切。
- 常规信息用列表、细分隔线和排版层级表达。按钮集中在获取作品、查看详情等有明确结果的位置。

Cinematic 可作为深色延伸，沿用相同内容与阅读规则。优先把主方向做到完整，再将成熟规则覆盖其他模板。

## 内容结构

| 模块 | 客户需要知道什么 | 设计处理 |
| --- | --- | --- |
| 开篇 | 为谁制作、哪一天、什么作品 | 一句短标题、新人信息、一张成片；获取作品的入口应容易找到 |
| 交付内容 | 收到了哪些文件 | 作品名称、简短用途、格式信息、按条目配置的获取入口 |
| 制作用心 | 制作投入带来了什么体验 | 先写可理解的观感，再提供工作流与技术说明 |
| 调色对比 | 前后有什么变化 | 每组包含标题、完整前后图、紧邻标签与可选短说明 |
| 观看保存 | 怎样正确观看和长期保存 | 下载原文件、播放器兼容建议、不同位置备份 |
| 反馈与署名 | 如何提出修改、由谁负责 | 时间点反馈示例、明确且可编辑的约定、克制的祝福与署名 |

“婚礼成片／航拍素材”是交付内容；“音频去噪／肤色精修”是制作服务，只有明确约定独立文件时才列为单独交付项。修改次数、反馈期限、编码、时长与 HDR／SDR 属性按实际项目填写，不能从模板或源素材截图推断成片参数。

建议保留技术证据能力：说明图、截图、参数与对应的一句解释可进入“制作详情”。客户主文档使用精选内容；更深入的证据可选择加入附录。Web 可折叠，PDF 必须明确选择是否纳入，不能依赖交互展开。

## 三种输出的排版原则

| 输出 | 排版原则 |
| --- | --- |
| PDF | 按阅读宽度选择页型；标题跟随首段，标签跟随图片，一组对比尽量同页；两张图实在放不下时重复组名并注明前后页关系 |
| 长图 | 连续阅读，段落间距有节奏；过长时按完整章节或完整对比分段，二维码与对应说明保持在一起 |
| Web（后续） | 响应式布局、真实观看与下载入口、可展开制作详情；可选交互对比，并保留不依赖拖动的前后查看方式 |

概念页里的横图在桌面左右展示，在手机上下展示；实际 PDF 和长图必须根据输出宽度决定布局。手机上每张横图如果只占半屏，会损失人物细节，不能只照搬桌面网格。

## 本轮概念产物

`release/design-concept-2026-09-28/index.html` 是独立静态概念页，使用参考 PDF 中的真实图像，未发布到外部网站，未改动现有工作台或导出模板。页首明确注明讨论稿；交付链接、访问密码、项目登录等仍未接入。文案用于讨论，不是向客户新增服务承诺。

概念页展示完整阅读顺序，支持桌面／手机排版、章节跳转和展开制作细节。浏览器打印样式仅为讨论便利，不能当作正式渲染器的分页验收。

参考图片只存放在本地忽略的 `release/` 内，不加入公开测试样本。没有将客户照片设为程序默认素材。

## 进入实现前需要确定的设计选择

1. 主方向是否采用浅色展册，深色作为扩展。
2. 首屏更偏重新人姓名，还是一句情绪标题；两者应有清楚的主次。
3. 制作报告默认深度，以及哪些截图需要进入附录。
4. 选定一份真实内容后确定手机 PDF 页型和最小字号。

之后的实现重点：可选择的封面素材与构图、结构化的制作说明与证据、按内容高度安排 PDF 分页、以及与输出一致的模板预览卡。当前五套模板卡片是风格示意图，正式设计阶段应提高其与实际输出的一致性。
