# 渲染、输出与 Windows 运行边界规格 v0.1

状态：编码前输出设计，供后续共同确认；以下验收场景为设计要求。后续实现与 Chromium 运行证据见 [实现说明](IMPLEMENTATION.md)，Windows 真机／实际手机尚待验收。
依据：[项目基线](PROJECT_BRIEF.md)、[MVP 总体设计](DELIVERY_STUDIO_MVP.md)。原设计阶段不写代码、不安装库；后续用户已要求继续开发，仍不重做现有 Worker。

## 1. 责任与最小范围

业务意图由 Project、DeliveryDocument、DeliveryItem、Comparison 表达；渲染只能读取经过检查的展示数据。
用户主要选择内容、视觉并检查结果；分页、尺寸预算、资源准备、任务恢复由应用层处理。
MVP 提供两个视觉模板、Split／Stacked 对比布局、按需 Full Width 单图，以及 PDF／PDF + 长图／长图三种输出选择。
两个模板的具体美术尚未设计完成；现有 Canva 内容、字体、Logo、Worker 源码和真实图片尚未收到。

| 层 | 输入与责任 | 不承担的责任 |
| --- | --- | --- |
| Preset | 复制初始内容、章节与可选视觉建议 | 持续覆盖已有项目 |
| DocumentBlock | 章节类型、内容引用、顺序、显隐、布局覆盖 | 配对识别、资产读取 |
| Component | 接收受控内容，生成结构与语义标识 | 查询客户数据库、决定交付承诺 |
| Template | 版本化设计变量、组件外观、默认布局和能力 | 客户文案、文件名规则、输出方式 |
| Layout | 对匹配的内容类型进行具体排布 | 修改 Before／After 关系 |
| RenderTarget | PDF 分页或长图连续画布，以及各自限制 | 修改业务数据 |
| RenderPlan | 固定尺寸、次序、资源版本与布局的目标专用计划 | 重新读取正在变化的草稿 |

业务公式保留为 Project Data + Template + Layout = Output；执行时显式加入 RenderTarget 和文档结构。
UI 发出编辑和导出命令；能力判断、布局解析、预检和快照建立属于应用层，共用同一套规则。

## 2. 模板与组件能力契约

TemplateDefinition 至少声明稳定 ID、版本、内容契约版本、支持的模块类型、输出目标、布局集合和默认布局。
同时记录设计变量、所需字体及版本、组件版本、内容长度策略、目标适用约束；引用的素材也必须有固定版本。
目标能力还需包含链接交互：PDF 支持可点击链接，长图只能显示文字／二维码，未来 Web 才支持页面内播放器和 Slider。
MVP 的两套模板应覆盖同一组核心模块和核心布局，允许风格差异，不能以切换模板为由删除内容。
未知模块、未知参数、缺失版本、目标不支持的布局必须产生关联问题；禁止忽略未知字段后假装成功。
模板允许有限的品牌颜色、字体角色和 Logo 配置；MVP 不接受用户脚本、任意 HTML、任意 CSS 或外部样式地址。

Component 的契约包括输入类型、必需引用、可选字段、支持的布局、分页规则和可访问标签。
例如 Comparison 组件接受稳定 Comparison ID 与两个已解析资产版本，Full Width 接受一张图；参数类型不相容则拒绝。
Component 的内容语义固定，Template 提供外观，Layout 提供排列；不得为每个模板复制一套业务组件。
正式渲染只允许许可明确、已随应用准备的字体；字体清单与覆盖范围须能检查，不能靠系统碰巧安装字体。
已安装模板升级产生新版本，旧导出保留其版本依赖；升级草稿先展示不兼容项，不静默迁移历史版本。

布局按以下优先级解析，每层先看目标专用配置，再看该层通用配置：

1. 当前 DocumentBlock 的人工覆盖。
2. 文档对该模块类型的默认布局。
3. 当前 Template 对该模块与目标的默认布局。
4. Component 声明的兼容默认布局。

显式选择不兼容时停在该层并提出修正，不悄悄跳到下层替换；未作选择时才使用后续默认值。
切换模板保留内容、显隐、顺序及人工覆盖，先计算兼容性；不兼容列表能定位到具体模块。
预检结果与当前草稿版本绑定。切模板、换图片、改尺寸或改布局后，与旧配置相关的确认应失效。
未来 Slider／Overlay 可以声明仅支持 Web；为 PDF 或长图转换成静态布局时，必须显示映射并由用户确认。

## 3. 手机阅读、图片比例与分页

制作工作台面向 Windows 桌面；交付预览默认按约 360–430 CSS 像素的手机显示宽度检查。
PDF 暂以 9:16 竖版试排、长图暂以 1080 像素宽试样；这不是已验证或已经批准的最终页面规格。
输出宽度、页面规格由 OutputProfile 管理，与模板分离；同一模板可以服务不同目标。
字体、行长、章节间距、标签和按钮式链接均须按手机实际缩放后的效果验收，不以桌面放大截图判断。

对比默认 Stacked，Before 在先、After 在后，并保持可见文字标签；不能只靠颜色区分状态。
Split 是可选布局；图片被缩小后不够清晰时提出建议，不自动改变人工布局。
图片默认完整显示、保留原始比例；背景色或留白用于容纳不同画幅，不通过拉伸把两图变成同一尺寸。
EXIF 旋转后再计算比例。相同比例但画面不对齐仍可能来自不同裁切，不能宣称系统已自动校准。
裁切属于展示配置，不改源资产；只有确认画面可对应时才能复用归一化裁切窗口，比例不同时须人工检查。
组内混合横竖图、极宽全景、极长竖图、低分辨率均进入排版检查；裁切后的细节不能被误称为完整画面。

PDF 的分页策略：

- 标题至少跟随一段正文或一项内容；交付列表可以按条目分页，续页保留必要上下文。
- Comparison 默认成对同页，先移动到下一页，再尝试在最小可读尺寸范围内排版。
- 仍不能容纳时，建议连续两页展示同一组 Before／After，保留相同组号和标签，或改布局。
- 跨页策略在文档级确认并保存，正式预览显示实际页序；不要求每组重复确认，也不拆分业务 Comparison。
- 正文过长按段落拆分；不可拆分单元仍超高时，说明具体模块并要求调整，不能截断或无限缩小。
- 不单独依赖 `break-inside: avoid`；分页计划和最终浏览器布局都要检查溢出。

长图使用连续节奏，不沿用 PDF 的空白、重复页脚或分页符；分段时优先章节边界并保留对比组完整性。
极高单组需要分段时同样保留组号和标签，不能直接从人脸或标签中间切开。
建议长图有交付链接时默认提供带用途标签的二维码和取件说明；PDF 保留可点击链接，不引入短链服务。
二维码只编码用户授权显示的稳定交付 URL，不编码 S3 临时签名地址、内部存储定位或系统凭据。
同机查看能否长按／从相册识别二维码取决于客户使用的应用，不能假定所有手机都支持。
过长 URL 导致二维码过密、压缩后不可识别或没有稳定链接时，长图预检必须指出无法可靠访问。
此时需明确替代方式，例如用户提供稳定分享链接，或确认随图片另发应用准备好的可复制交付文字；不能把图片内的网址画成可点击按钮。
只生成长图也需要可用访问方案；替代方式确认后记录到输出检查，实际二维码尺寸与分享后识别能力须真机验证。

## 4. 展示数据白名单与资产读取

渲染输入是 DisplayDocument，由应用层按本次可见字段显式组装，不能直接把 Project 或数据库记录传给模板。
允许字段包括此次客户称呼、新人展示信息、可见日期、公开品牌信息、已显示交付内容、文案、对比信息和展示资源引用。
内部备注、隐藏字段、源绝对路径、目录扫描清单、账号信息、S3 凭据、密码散列、服务令牌一律不进入展示输入。
百度网盘提取说明或其他客户可见口令仅在用户明确选择显示的字段中出现，不能自动从内部配置复制。
DisplayDocument 的资源使用应用分配的稳定引用；渲染器通过该 revision 的授权清单读取，不接受任意本地路径。
渲染资源与可点击交付链接是两种字段：外部交付链接可以呈现，渲染器不因此访问其内容。
文本安全转义；链接只接受允许的协议，拒绝脚本和本地文件地址。资源请求仅允许受控应用资源与已固定字体。
隐藏内容不得留在 PDF 文本层、HTML 隐藏节点、图片元数据或未来 Web 返回数据中；CSS 隐藏不构成数据隔离。

参与输出的照片先准备不可变文档副本和标准派生资源，处理方向、ICC 到 sRGB 的转换与无关元数据清理。
保留源图不变；对 Before 与 After 使用一致的技术处理，不自动调整曝光、肤色、锐化或增加风格滤镜。
缺失／无法解释的颜色配置必须可发现；是否按无配置 sRGB 解释需要明确策略，并保留已知限制。
字体加载完成不证明没有缺字；预检还需核对实际字符覆盖、失败资源与替代字体情况，尤其是新人姓名中的生僻字。
跨设备屏幕和 PDF 阅读器会造成显示差异；本规范只约束输入和生成过程，不承诺所有手机颜色完全一致。

## 5. 预览候选、导出版本与午夜一致性

“导出最新草稿”先由应用用例提交并等待当前编辑命令保存成功，取得对应 draftRevision 回执。未保存、保存中、保存失败或冲突时不得提交旧候选，即使数据库中的旧版本尚未变化。UI 仅反映状态，不能独自承担这一校验。
编辑预览读取最新草稿，允许低分辨率图片和动态“今天”，明确标为快速预览。
正式预览创建 PreviewCandidate：固定 draftRevision、模板／组件／布局版本、输出配置、工作室时区与解析日期。
候选同时固定品牌快照、可见数据、资产版本和内容哈希、派生参数、字体文件校验值、渲染器及 Chromium 版本。
正式预览由受控渲染器生成，呈现 PDF 页界或长图最终分段；浏览器工作台的快速预览不是像素一致性的证据。
可复用已生成的候选产物，避免确认后无意义地重新渲染；是否采用该优化属于实现选择，不承诺当前性能。

候选在以下任一情况后过期：草稿版本变化、被引用的管理副本损坏／缺失、模板或输出配置变化，以及影响日期解析的工作室时区变化。仅发现源图新版本但未采用时，不改变候选已固定的图片。
当可见交付日期为自动模式时，尚未提交的候选跨工作室日历日也过期；应用自动重建并提示日期变更。
例如 23:59 正式预览为 9 月 26 日，00:01 点击生成：先刷新为 9 月 27 日的正式预览，不静默导出旧日期。
只有更新后的正式预览就绪，才接受针对新候选的生成命令；不能在后台换了日期却继续使用旧预览的确认。
手动日期不随午夜变化；隐藏日期不进入展示数据，不因其不可见的自动值触发无意义重建。
正式候选与日期边界均以本机服务维护的工作室时区规则判断，不能由不同标签页各自决定。

提交时原子校验候选对应的 draftRevision 与依赖清单，再固定 ExportRevision；校验失败提示预览已更新并重建。
两个标签页同时编辑使用乐观版本检查，冲突不得最后写入覆盖；旧标签页不能直接导出另一个标签页修改前的草稿。
历史版本重导是明确独立操作，允许选择已固定旧 revision；不能把“导出最新草稿”的冲突当作历史导出自动处理。
已提交的 ExportRevision 永不随时钟或草稿改变；跨午夜生成及次日重试仍使用原日期与资产版本。
一次 PDF + 长图共用一个 ExportRevision，两个目标不分别计算“今天”，也不各取一次当前客户资料。

## 6. 输出任务、失败与恢复

ExportRevision 保存不可变输入；ExportJob 保存执行状态；Artifact 保存实际文件、目标、尺寸、大小与校验信息。
每个目标有独立状态与尝试记录，可处于预检阻塞、待处理、运行、成功、失败、取消；预检阻塞标明影响范围，未执行的目标不能伪装为已尝试渲染。
总体状态区分完成、部分完成、失败和取消。只有所有选中目标成功才显示全部完成。

| 问题范围 | 例子 | 行为 |
| --- | --- | --- |
| 共用输入 | 可见 Comparison 缺图、快照关联失效 | 阻塞所有依赖它的选中目标 |
| 仅 PDF | 不可容纳的分页、PDF 写入失败 | PDF 标记阻塞／失败，长图可继续 |
| 仅长图 | 超过图片尺寸预算、编码失败 | 长图标记阻塞／失败，PDF 可继续 |
| 未使用数据 | 隐藏且未引用图片损坏 | 提示资产问题，不阻塞本次输出 |

正式候选包含共用展示快照和每个目标各自的计划／预检状态。共用输入有效且至少一个目标正式预览就绪时，可以明确选择“先生成可用目标”；保留其余目标阻塞的记录，不能将双输出选择静默改写为单输出全部成功。
预检先显示预计能完成的目标；若选中目标部分被阻塞，应明确告知部分完成范围，不把可生成产物也全部扣住。某目标无法形成正式预览不会使另一目标的有效预览失效。
相同快照和相同问题指纹的风险确认可复用；变更了相关内容或配置则重新检查，不能永久忽略同一错误代码。
资源准备完成并验证后才启动渲染；等待字体、图片解码和页面布局稳定，动画关闭，并检查空白、溢出与截断。
先写应用管理的暂存文件，校验格式、非空、预期页数／尺寸及校验信息，再原子登记为成功 Artifact。
失败不能覆盖此前成功文件；PDF 成功而长图失败时可直接取得 PDF，单独重试长图。
失败目标重试沿用同一快照；调整尺寸、布局或内容属于新候选／新 revision，必须重新预览。
关闭页面不等于取消本机后台任务；应用退出或崩溃后将未完成尝试标记中断，恢复时仅重新执行未完成部分。
恢复前核验成功产物仍存在且校验通过；文件丢失不能仅凭数据库中的成功标记报告可下载。
导出成功表示产物可用；浏览器下载完成、用户发给客户、客户已阅读都属于不同事实。

## 7. PDF 与长图的执行取舍

建议 HTML／CSS + Playwright 驱动固定 Chromium，PDF 使用打印接口，保留可选择文字和链接，不将每页降为截图。
页面规格、打印背景、页边距、缩放比例、字体包及地区设置纳入输出配置；纸张尺寸不能由模板暗中决定。
正式 PDF 预览应依据实际生成 PDF 的页序和边界；快速 HTML 预览只能检查内容与近似排版。
模板和渲染器应有共同维护的兼容矩阵；更新 Chromium 后验证代表性文档，再提升默认渲染版本。

长图采用受限高度的分块渲染，按明确坐标合成，检查接缝、重复区域与遗漏区域。
仅分块截图仍可能在最终编码阶段用满内存；预算需覆盖浏览器、图像解码、合成缓冲区和编码器。
例如 1080 × 60000 的单个 RGBA 缓冲约为 247 MiB，实际峰值还要叠加其他工作内存，不能视作安全输出尺寸。
开始任务前评估目标宽高、总像素、编码格式限制、预计磁盘空间和工作预算；运行时也需监控超限并可恢复失败。
单图上限依据 Windows 实测、编码器和主要手机／分享渠道确定，当前不假定存在一个通用安全最大高度。
超限时建议按章节分为多张或降低宽度，并显示对清晰度的影响；用户未选择策略前不能静默拆图或截尾。
确认的分段策略可保存到文档输出配置；改变分段数量时仍应在正式预览和产物摘要中可见。
JPEG 是照片内容的候选默认格式；压缩参数和 PNG 支持须由真实样张决定，不能先承诺文件体积与阅读质量。

历史快照保留依赖清单和文档用图；只保留哈希不足以复现已丢失素材。
缓存可删除，引用中的文档资源和成功产物不可按缓存清理；后续保留策略需明确区分这些类别。
原渲染器停止支持或依赖缺失时，显示不可按原环境重建；已有产物仍是历史事实，不冒充可逐字节重现。
用新版渲染器迁移后生成应产生新 revision 并重新检查，不改写原版本。

## 8. Windows 浏览器与本机服务

建议 Edge／Chrome 工作台 + 同机 Node 服务 + SQLite + Sharp + 受控 Chromium，采用模块化单体。
本机服务提供生产页面与接口，使用同一个固定 loopback origin；开发服务器不作为用户发布方式。
origin 由协议、主机和端口共同决定。改端口，或在 localhost 与 127.0.0.1 间切换，都会影响浏览器中的授权和存储。
启动器发现端口占用时先核验是否为本应用实例；不能杀掉未知程序，也不能静默换端口并假装原目录授权仍在。
需要调整 origin 时保留本机数据库与管理素材，并明确要求重新建立浏览器目录绑定。

目录选择必须由用户操作触发，并在受支持的安全上下文中调用；loopback 的具体权限行为要在目标浏览器验证。
文件夹拖入和选择文件夹共用导入接口；拖入能力不足时提供显式文件夹选择，不要求逐个上传。
目录句柄可尝试保存在该浏览器 origin 的 IndexedDB，但权限可能被撤销或要求重新授权，不能当作永久后台授权。
浏览器配置切换、清除站点数据、换电脑或云端域名均不能自动继承句柄；设备专属 RootBinding 记录授权状态。
兼容性的目录选择输入可能只提供 File 与相对路径，不提供可持久化句柄；按实际能力区分重新扫描流程。
目录句柄不能序列化成服务器可用的绝对路径；本机服务只接收索引和实际选择导入的必要文件内容。
批量扫描先读名称、相对路径、大小等信息，完整视频不默认读取字节、完整哈希、上传或转码。
必要文档用图落入应用管理目录后，导出不依赖浏览器原目录权限；重新扫描源目录才需要恢复授权。
关掉网页后持续监控本机目录属于未来本地连接程序的能力，MVP 不以网页获得的句柄承诺该功能。

服务只监听 loopback，校验 Host 与允许的 Origin，使用启动会话授权及请求防护，不把“只在本机”当作完整防线。
不用管理员权限常驻；服务以当前用户权限工作，文件接口限于受管理资源或明确授权根目录，不暴露任意读写路径 API。
拒绝来源不明的写请求，防止路径穿越和不受控外部资源抓取；渲染进程只读取本次授权资源，执行时间与内存受限。
打包需包含或可靠准备 Node、原生数据库／图片依赖、Chromium 和许可明确的字体；不能要求用户先搭开发环境。
启动、停止、异常日志、数据位置、磁盘不足、升级和卸载时保留用户数据，都属于 Windows 交付体验的验收范围。
当前优先不引入 Electron／Tauri；一键启动器与安装器是否足够，须通过实际安装和浏览器流程检验。

## 9. 云端与现有 Worker 的边界

未来 HTTPS 后台使用云端身份和租户范围接口；不是把本机端口公开，也不让云端服务器直接读取 Windows 路径。
浏览器继续在用户授权内扫描，上传范围明确显示为元数据和必要文档素材；完整婚礼视频保持百度网盘等既有存储。
本地 RootBinding 不作为可迁移权限；迁移保持 Project／Asset 等 ID，验证资产完整性，并重新绑定设备访问。
未来如云端页面调用本地连接程序，涉及浏览器本地网络权限、来源绑定与配对认证，需单独设计，当前不把它当作自动可用。
云端渲染任务必须带租户授权上下文；资产解析、缓存键、任务记录和产物下载都需要隔离，不能只依赖 UUID。

既有 Worker 暂作待适配 Web Template；尚未取得源码，当前不改页面、不发布、不替换视觉。
后续由固定交付版本生成 Web 展示数据，通过适配器映射品牌、新人、日期和影片；管理后台字段不直接序列化给客户。
Publication 单独记录版本、唯一链接、访问策略与撤销状态；密码验证由服务端执行，限制尝试，客户无需注册。
密码只保护页面而视频对象公开时，媒体仍可绕过访问控制；S3 短片需配合私有对象和受控、短时访问方式。
固定存储引用使用提供方／对象键，临时签名 URL 在访问时生成；凭据与密码散列不放入模板、PDF 或公开展示数据。
Web 专用布局可响应式交互；新增目标适配器读取同一业务身份与交付快照，不复制另一套客户和 Comparison 模型。

## 10. 验收案例与证据要求

以下全部为计划案例，状态均为未运行；文档审阅不能替代 Windows、浏览器、PDF 阅读器和手机验证。

| 案例 | 可接受结果／需要的证据 |
| --- | --- |
| 同文档切换两模板，保留手动 Split | 内容和顺序不变；不兼容覆盖明确定位；两套最终产物与项目记录 |
| 横竖混合、极高图片与长文案 | 无拉伸、截断、不可读缩小；跨页策略记忆到文档，预览与产物页序一致 |
| 23:59 预览，00:01 首次提交 | 自动日期重建并可见；旧候选拒绝提交，新候选日期进入两类输出 |
| 23:59 已提交，次日重试长图 | 两目标 revision、日期、品牌与资产版本相同；PDF 不被覆盖 |
| 标签页 A 预览后，B 修改新人姓名 | A 检测版本冲突并刷新；不能无提示输出过时草稿 |
| 新编辑保存失败，数据库仍为旧版本 | 当前“导出最新草稿”不能提交旧候选；成功保存取得回执后重新预览，历史版本重导另行明确选择 |
| PDF 分页阻塞，长图可生成 | 明确部分完成；长图可取得；修复 PDF 的新 revision 与旧产物有区别 |
| 图片源被覆盖／目录权限撤销 | 已固定管理副本的旧产物可用；新扫描提示变化或重新授权，不悄悄换图 |
| 生僻姓名、缺字体、断网导出 | 缺字／缺资源可发现；已完整安装的资源无需外部字体请求；检查 PDF 文本层 |
| 超长文档、磁盘不足、途中退出 | 没有截尾和假成功；预算提示、可恢复失败与实际磁盘文件记录一致 |
| 隐藏备注、外部图片地址、本地路径注入 | PDF 文本／元数据及 Web 展示输入无泄漏；不请求未授权资源 |
| Windows 新账户安装、端口占用、升级 | 不要求管理员常驻和开发依赖；授权状态解释准确；已有数据保持可用 |
| 手机接收 PDF／长图 | 真机阅读标签、姓名、链接／二维码和细节；经实际分享渠道后仍满足确认的质量标准 |
| 只生成长图且有百度网盘链接 | 显示用途标签、二维码和已授权取件说明；实际渠道压缩后可识别，否则检查指向明确替代访问方式 |

只有 Windows 真机才能确认本方案的本机部署体验：安装签名／系统提示、原生依赖、浏览器目录权限、中文路径、文件锁与更新行为。
浏览器与手机矩阵还需覆盖受支持 Edge／Chrome 版本、至少常用手机 PDF 阅读器和用户实际分享渠道；当前不报告任何通过率。
实施前先用一份真实交付文档、代表性图片与许可明确字体锁定输出规格，再以这些案例建立基准；不得把方案合理性写成运行证据。
