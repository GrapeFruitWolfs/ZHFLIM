# Wedding Delivery Studio：实现与验收边界

初始记录：2026-09-26；最新能力与升级边界见 [v0.2.0 说明](RELEASE_0_2_0.md)。本文件保留初始 MVP 的实现与历史验证记录，不将设计规格中的未来功能算作已实现。

## 当前可用范围

- 项目列表、创建／复制／归档／重开；自动保存、修订冲突提示、保存失败时保留输入并支持下载草稿副本。
- 新人资料、字段显示开关、自动／手动交付日期、工作室品牌及 Logo、内部备注。内部备注与隐藏字段不会送入客户文档。
- 稳定 ID 的可排序章节与 DeliveryItem：标题、描述、格式、显示状态、下载／播放链接、取件说明；内容库与自定义文字。
- 三个可编辑的初始方案和保存个人方案。复用方案／复制项目不会自动带入客户链接和调色照片。
- 目录拖入／选择、分批读取文件信息、可取消导入。默认只读取候选对比 JPEG／PNG 的内容；不会上传整部婚礼影片。
- `-1/-2` 可切换顺序、before/after 命名、手动规则。Comparison 使用独立 ID，绑定明确 AssetVersion；文件名仅参与识别。
- 导入报告、缺图与冲突提示、交换／隐藏／拆组／排序／替换图片、撤销最近一次关系调整；同来源重扫保留人工覆盖。
- Editorial、Cinematic、Archive、Correspondence、Gallery 五套模板；Stacked、Split 两种独立布局；PDF／长图／两者三种输出配置。
- Chromium 真正渲染的手机比例 PDF 和 JPEG 长图、PDF 链接与长图二维码、可选安全边界分段／对比分页。
- 内容预检、字体字形检查、托管图片哈希校验、输出资源预算、正式预览、固定版本导出、按目标保留成功结果和重试。

以上模板是本次实现的起始视觉，不是对用户 Canva／Worker 的复刻，也未经真实婚礼内容的最终美术验收。

## 数据与工程边界

```text
src/
├── shared/       项目、素材、Comparison、输出契约与可编辑预设
├── domain/       数据校验、识别、人工覆盖与错误类型
├── server/       Fastify、本机会话、SQLite、导入与导出应用服务
├── rendering/    客户可见数据白名单、字体、模板、HTML、Chromium 输出
└── ui/           React 工作台、保存协调、目录输入和预览
public/fonts/     随包字体与许可证，不依赖线上字体
tests/            领域/API/真实输出与浏览器端到端测试
scripts/          Windows 启动器和便携打包脚本
```

React／TypeScript／Vite 负责交互，Fastify 负责本机 API，Node 24 内置 SQLite 保存项目聚合及记录。Sharp 管理图像方向与 sRGB 副本，Playwright／Chromium 生成 PDF 与长图。

核心路径：`Project → DisplayDocument → Template + Layout + OutputTarget → Artifact`。DisplayDocument 在渲染前剔除不显示的字段。Template 只定义设计变量和样式，Layout 处理具体模块排列；输出目标不修改业务数据。

MVP 用 SQLite 中带 tenantId 的聚合记录保留边界，不为每个概念建立独立服务。Client 当前只有稳定身份和项目内信息，尚未建设独立 CRM。tenantId 由本机工作室管理，不接受请求任意切换；这不是已经完成 SaaS 身份隔离的承诺。

素材保留原始哈希与规范化副本哈希。Comparison 固定 assetId／versionId，发现源文件变化时不自动替换已选版本。源目录不必永久保持在线，输出使用本机管理的副本。

正式预览与输出绑定草稿修订、解析日期、模板、字体、素材版本与渲染依赖。修改后须重新预览；旧导出不随新草稿变化。生产渲染只使用本地受控资源，不自动抓取任意 URL。

## 当前限制

- Windows x64 为目标平台；当前构建环境为 Linux。Windows 便携包只能证明文件、版本、原生二进制与打包检查通过，不能替代真机启动、重开、导出和升级测试。
- 浏览器工作台现在连接本机，不是浏览器登录云端。无 CRM、日历、账单、多人协作、远程发布、客户密码页或分析。
- 现有 Worker 未提供源码，保持未改动；S3／百度网盘只使用交付链接，没有自动上传、自动同步或权限管理接口。
- 附件打包尚未支持，UI 明确禁用；交付描述不能等同于已核验远端文件存在，也不能验证网盘链接未来是否到期。
- JPEG／PNG 是当前对比图片输入。RAW、HEIC、视频解码等不在此版范围，识别报告会区分不支持或仅索引的素材。
- 不监视任意本机目录；网页读取文件夹需要用户当次授权选择或拖入。重开浏览器后需重新选源目录才能重扫。
- 不支持任意模板代码、Slider 或播放器；静态 PDF／长图不能提供网页交互。
- 超大内容被明确预算保护，可能需隐藏部分对比／分文档交付。未做数十万文件目录、真实大批量照片或低配 Windows 机器基准测试。
- 当前一次输出预算：100 组可见对比、估计 120MP 解码像素、512MiB 引用原图、256MiB 管理副本、96MiB 渲染 HTML；单张导入图片不超过 40MiB。这些是保护上限，不是全部条件都能同时达到的性能保证。
- 快速预览不是最终分页结果；PDF 浏览器内嵌查看是否可用取决于浏览器，也可下载后打开。
- 本地服务仅绑定回环地址，带本机会话与写入令牌校验；没有用户登录、静态文件加密或公网部署所需的完整安全体系。
- 历史预览与原图会占磁盘，尚无自动清理／配额／一键备份。备份需退出程序后复制完整数据目录。

## 平滑演进

下一阶段先使用一份脱敏的真实交付资料检验内容与视觉，再考虑云端：引入账号与租户权限、远端元数据仓库／任务队列、必要的文档图片对象存储，保留本机目录连接能力。导出契约和 Comparison 身份保持稳定。

Web Delivery 作为新增目标适配既有 Worker，由 Publication 管理不可猜链接、密码、访问限制和撤销；仅向客户下发白名单快照。完整婚礼素材仍由百度网盘承担，预告和短片由用户 S3 承担。公网认证、租户隔离和存储权限需单独验收，不能直接把当前本机服务搬上云端。
