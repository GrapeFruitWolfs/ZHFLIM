# Wedding Delivery Studio：领域与导入规格草案 v0.1

状态：编码前领域设计，待结合真实模板和素材确认。后续已进入实现，代码与测试状态见 [实现说明](IMPLEMENTATION.md)；本文概念模型不等于当前全部实现。
依据：[需求基线](PROJECT_BRIEF.md)、[MVP 总体设计](DELIVERY_STUDIO_MVP.md)。
本文细化对象归属、唯一事实来源、素材版本、自动识别和人工修改的边界。
字段是概念契约，不表示必须为每一行建立独立数据库表；内部结构不得直接暴露为客户页面数据。

## 1. 统一约定

- 业务对象使用稳定 ID；显示序号、文件名、路径、项目编号都不是 ID。
- `tenantId` 表示 Workspace 的数据归属；本机版只有一个工作区，也使用该边界。
- 草稿数据唯一事实来源是应用数据库；目录索引、文件名和导出 JSON 均不能反向自动改写草稿。
- `documentId` 表示一次交付文档；MVP 默认每项目一份，但不把它与 Project 合并。
- 持久模型包含 `schemaVersion` 或受统一迁移版本约束；草稿修改有递增 `draftRevision`。
- 所有排序在所属容器内解释，使用稳定 ID 解决相同顺序值；序号由显示位置计算。
- 状态和缺失检查由应用层推导，UI 不自行解释文件名、复制方案或决定是否能导出。

## 2. 对象与最小字段

| 对象 | 最小字段／关系 | 唯一职责 |
| --- | --- | --- |
| Workspace | id、name、timezone | 归属和自动日期的时区 |
| BrandProfile | id、tenantId、name、logoVersionRef、signature、visualDefaults | 可更新的工作室默认品牌资料 |
| Client | id、tenantId、addressing、people、contact | 当前客户资料；联系人不等于公开展示资料 |
| Project | id、tenantId、projectNo、clientId、weddingDate、internalNotes | 婚礼项目长期身份 |
| DeliveryDocument | id、tenantId、projectId、displaySnapshot、deliveryDate、templateRef、outputPreferences、draftRevision | 此次交付草稿 |
| DocumentBlock | id、documentId、type、visible、order、layoutOverride | 章节级显隐、顺序及布局覆盖 |
| DeliveryItem | id、blockId、title、description、format、visible、order、method、resources | 交付清单内部条目 |
| ContentModuleDefinition | id、version、scope、contentType、title、defaultContent | 可复用的受约束文案定义 |
| ContentModuleInstance | id、blockId、type、title、content、sourceDefinitionRef? | LOG 工作流、保存建议等结构化文案 |
| Comparison | id、blockId、title、description、visible、order、before、after、reviewState | 对比集合内部的一组关系 |
| Asset | id、tenantId、projectId 或 brandScope、mediaKind、latestKnownVersionId | 媒体的稳定身份 |
| AssetVersion | id、assetId、contentHash、byteSize、mimeType、mediaMetadata、createdAt | 一次不可变的媒体内容 |
| AssetLocation | id、versionId、kind、locator、availability、lastCheckedAt | 内容的来源与可取得位置 |
| AssetDerivative | id、sourceVersionId、recipeVersion、parameters、storageKey、hash | 由特定源版本产生的缩略图／文档图 |
| ImportRoot / RootBinding | 根目录逻辑身份／设备上的目录授权 | 目录来源与设备读取权限分离 |
| ImportRun / FileObservation | 本次进度、统计／相对路径、轻量信息、内容映射 | 导入过程事实，不是交付承诺 |
| RecognitionDecision | projectId、documentId?、对象／来源范围、operation、reason | 记住人工排除、拆分、删除等决定 |
| PresetVersion | presetId、version、模块初始值、可选视觉建议 | 可复制的初始配置 |
| ExportRevision | id、documentId、sourceDraftRevision、snapshot、dependencies | 一次固定的导出内容 |
| ExportJob / Artifact | revisionId、target、状态、错误／文件、校验信息 | 执行过程与结果分离 |

`people` 可保存多个有显示名和可选角色的新人，不依赖“必须一男一女”或拼接姓名作为主键。
`format` 可扩展，但值与说明要有定义；播放地址、下载地址、时长和字节大小是不同字段。
`resources` 中的媒体引用使用 ID；外部整包链接使用资源类型和用途，不伪装成单一 Asset。
上述归属可由父关系推导；若重复保存 tenantId／documentId，必须校验相等，不能形成两个独立答案。

## 3. 内容与展示的唯一事实来源

```text
DeliveryDocument
└─ DocumentBlock（章节顺序、章节显隐、布局）
   ├─ deliveryList → 多个 DeliveryItem（条目顺序、条目显隐）
   ├─ content → 一个 ContentModuleInstance（仅文案）
   └─ comparisonGallery → 多个 Comparison（组内顺序、单组显隐）
```

- 每个内容实例在 MVP 只有一个父 Block；同一内容重复展示时创建独立实例，不共享可变对象。
- ContentModuleInstance 不包含 `visible` 或 `order`；这些值全部来自其一对一父 Block。
- DeliveryItem 和 Comparison 的 visible/order 只作用于列表内部，不与 Block 的章节配置重复。
- 实际显示条件为：父 Block 可见，且对应条目可见；父章节隐藏不会修改子条目保存的选择。
- 不再另存 `document.itemsOrder`、`template.blockOrder` 等同义状态；模板默认顺序仅用于初次创建。
- 具体 Layout ID 及参数放在 Block 的展示配置；如支持单组覆盖，则放在 Comparison 的展示配置子项。
- 样式切换不得改动标题、内容、条目显隐、顺序、配对或用户已经选择的布局覆盖。
- 隐藏是保留内容但排除展示；删除是移除草稿实例，两者不等价。
- ContentModuleDefinition 提供可复用默认文案，例如 LOG 工作流；其内容类型先限于受约束的 text／list。
- 添加模块时复制定义为实例，记录来源版本用于解释和后续比较；定义更新不实时覆盖项目实例。
- 用户可以改标题、正文和列表项；模块语义由定义表达，不把“肤色精修”硬编码成必须存在的业务开关。
- MVP 可只提供内置定义和通过 Preset 保存修改后的组合，不要求独立建设内容库管理页。

## 4. 客户快照、日期和字段显隐

- Client 保存当前客户记录；创建文档时复制公开称呼、新人显示名等到 displaySnapshot。
- 联系方式默认不进入展示快照；内部备注始终由私有字段保存，不使用“默认隐藏”替代隔离。
- Project 的婚礼日期是项目事实；文档创建时复制到本次展示快照，供本次交付独立校对。
- 用户之后修正 Client／Project／BrandProfile 时，系统可提示更新当前草稿；不无提示同步或改历史版本。
- 文档品牌也保存选定的品牌展示值和 Logo 版本；之后修改默认品牌不会暗中改变旧文档。
- 普通展示字段由 `value + visible` 表达；显示为空和隐藏有不同语义。
- 交付日期由 `mode: auto/manual + manualDate? + visible` 表达，不用空字符串代表所有状态。
- 婚礼日期和手动交付日期用日历日期；导入、修改和生成事件用带时区语义的时间戳。
- 自动交付日期按工作区时区解析；正式预览候选一次固定内容、日期和依赖版本，显示将用于本次输出的值。
- 可见交付日期采用自动模式且候选尚未提交时，跨过工作区日历日会重建候选并标明日期变化；手动日期不随日历日变化，隐藏自动日期不触发重建。
- 提交时复核草稿版本和依赖，沿用校验通过的候选建立 ExportRevision；PDF 和长图共享该固定日期。
- 已提交 ExportRevision 次日重试仍使用原日期，不能在任务执行时再次读取“今天”。
- 仅根据可见内容验证必填字段；隐藏日期不要求人工补日期，隐藏内容也不会意外出现在客户数据中。
- 具体哪些客户字段必填仍需实际模板确认；占位符未替换属于可检测问题，不擅自推定新人姓名。

## 5. 交付条目与文件发现

- `method` 建议为外部链接、附件、线下交接、仅说明；链接仅在交付方式要求时必填。
- DeliveryItem 是交付意图。发现“航拍”目录或音频文件，只产生发现事实和可接受建议。
- “完整成片 + 百度网盘下载链接”可以完整成立，不要求完整视频同时存在于本机管理存储。
- 文件大小、时长、封面属于可选描述；系统不凭目录名称编造数量、格式或交付完整性。
- 外部链接的访问检查状态另存为未检查／可达／失败及检查时间，不把“可达”理解为客户一定有权限。
- PDF 可产生点击链接；长图中重要访问入口必须有可读地址、二维码或明确获取说明，具体形式由输出规格决定。
- 提取码等客户取件说明按该条目显隐输出；存储账户凭据永不成为条目字段或渲染输入。

## 6. Asset 身份、内容版本和位置

- Asset ID 表示同一个被管理的媒体对象；AssetVersion ID 表示其某次实际内容。
- AssetVersion 的内容哈希、媒体元数据和内容本身一经记录就不修改；源文件覆盖产生新版本。
- latestKnownVersionId 只表示最新发现，不能被渲染器自动解释为“当前使用”。
- 草稿引用固定到 `{assetId, versionId}`；导出快照继续固定同一版本及所用派生资源。
- AssetVersion 内不保存可变“在线／缺失”状态；位置可用性由 AssetLocation 表达。
- 一个版本可有源目录位置和本机副本等多个位置；只要可信管理副本可用，源目录移动不使交付失效。
- 用户明确“更新同一图片”时可延续 Asset ID；拖入另一画面替换槽位则关联另一 Asset，不覆写旧版本。
- 内容哈希用于验证已读取字节和存储去重，不作为业务 ID，也不跨工作区提供存在性查询。
- 文档图片保留原始导入字节；EXIF 方向和 sRGB 转换生成可追溯派生图，不能直接改写原始版本。
- 缩略图可丢弃重建；历史输出依赖的原图、版本化文档图和品牌资源必须有明确保留引用。
- 仅在源位置记录的大视频不具备不可变内容保障；在读取并校验前，它只是 FileObservation 或外部引用。
- 普通编辑界面无需显示版本对象；发现源图改变时提示“发现更新，查看并采用”，内部版本不增加日常操作。

## 7. Comparison 的草稿与确认语义

- before／after 槽位各保存固定素材版本引用，允许草稿暂缺一侧。
- 自动匹配保存规则 ID、规则版本和短原因；显示编号由排序产生，不参与业务关联。
- 配对完整性由槽位和素材可用性推导；reviewState 单独表示自动建立／人工确认／需要复查。
- 每次人工交换、替换、拆分或组对都增加关系修改序号，异步识别结果不能覆盖较新的人工操作。
- 人工确认保护的是用户的当前关联及版本选择；重新扫描不能交换槽位、换新版本、恢复旧顺序或取消隐藏。
- 发现当前槽位的源文件改变时，创建更新建议；旧副本继续用于预览，用户接受后才更新草稿版本引用。
- 更新建议展示本次文档中受影响的槽位并确认范围；不因接受一次更新而改动其他文档的引用。
- 接受更新后，原人工“这是同一组”的关系保留，但标记需要复查视觉；历史导出继续使用旧版本。
- 两边意外引用同一内容版本时明确提示；建议允许用户确认确实无差异，不以猜测调色效果为阻塞规则。
- 可见组缺图或图片不可解码阻止该次输出；隐藏组的问题保留在素材清单但不阻止无关内容导出。
- 删除自动组／拆开误组写入 RecognitionDecision；自动扫描不应不断把用户删掉的结果重新建立。

## 8. 导入管线与权限

```text
选择目录 → 分批列出相对路径和轻量信息 → 识别候选与问题
        → 读取必要图片并校验管理副本 → 形成可重复提交的导入记录
        → 建立唯一明确配对／待确认建议 → 检查本次交付意图 → 显示报告
```

- ImportRoot 属于一个项目并具有稳定 ID；RootBinding 是“设备 + 浏览器 + 本地授权”的绑定。
- 浏览器目录句柄留在设备存储，业务数据只保存绑定标识；未来云端不能使用该句柄读取 Windows 文件。
- 相对路径是来源定位线索，绝对路径、设备句柄和授权信息不进入客户输出或共享项目数据。
- 拖入不支持持续目录句柄时，允许一次导入并告知重扫需重新选择；不能宣称后台持续监控目录。
- 索引不是上传：先报告数量／类型／候选图片；只读取并传递实际候选文档图，不复制整套视频。
- 本机服务也不能根据网页提交的路径任意读取磁盘；使用浏览器传来的授权文件内容。
- 管理副本完成写入和哈希验证后，数据库才能将它登记为可用；临时文件不能被预览或导出引用。
- 若复制时文件变化或读取中断，记录失败／重试建议；不把未完成字节当作成功的新 AssetVersion。
- 各批次可独立落盘，取消后保留已完成的明确结果，并展示已导入／未处理数量，不伪称全批完成。
- 自动识别期间允许继续编辑；最终应用建议时重新检查 draftRevision 和相关人工决定，过期建议丢弃或重算。
- 权限失效时要求重新选择目录；已经有管理副本的文档仍可编辑、预览和导出。

## 9. 去重、重命名和同名新内容

| 输入变化 | 身份与数据处理 | 是否自动改当前文档 |
| --- | --- | --- |
| 同根、同路径、同内容再次导入 | 复用原 observation 映射、Asset 和版本 | 不创建重复组 |
| 大小／时间未变 | 只作快速扫描线索；所用图片读取后仍校验内容 | 不能宣称字节相同 |
| 同根同路径、内容哈希不同 | 新 AssetVersion，保留旧管理副本 | 提示更新，不自动替换槽位 |
| 同根原路径消失，新路径唯一匹配原内容 | 更新来源位置，延续 Asset 和版本 | 关系与人工决定不变 |
| 多个重命名候选匹配同一内容 | 保留候选，要求选择来源映射 | 不随意合并身份 |
| 不同路径存在相同字节 | 复用底层存储，可记录多个来源；标记逻辑重复 | 不因哈希相同丢掉候选语义 |
| 不同目录都出现 01-1／01-2 | 以根和相对父目录区分识别组 | 可产生独立 Comparison |
| 同组 01-1.jpg 与 01-1.png 都匹配 After | 产生多个候选冲突 | 不选择最后一个文件覆盖 |
| 新选择目录可能是已导入根的迁移副本 | 提示重新绑定已有根或作为新来源 | 不根据目录显示名自动认定 |

相同字节不同路径的去重只保证存储和重复提示；逻辑 Asset 仅在来源映射确定或人工合并后复用。
这避免把真正的两个制作对象因字节恰巧相同而强行合并；同一来源重扫仍具有幂等性。
不为数十 GB 视频逐个计算完整哈希；未读字节的观察结果始终标明验证范围。

## 10. 识别优先级与不复活规则

1. 当前人工关联和人工排除记录优先。
2. 当前项目明确选用的命名规则只处理尚未决定的候选。
3. 内置 before／after 等规则在候选唯一且不冲突时建立关联。
4. 相似文件名、时间接近等弱线索仅提出建议；MVP 不加入无法解释的视觉置信度。

- `01-1 → After；01-2 → Before` 是一个版本化规则；根／父目录／编号只构成识别分组线索。
- 导入记录保存稳定的来源组 ID、资产集合和已建立的 Comparison ID；解析编号只是来源属性。
- 自动建组以文档和来源组作为幂等范围，事务提交时校验已有映射，避免重复请求或并行扫描创建两组。
- RecognitionDecision 的作用范围明确为项目资产排除或文档内关系决定，不能含糊地混为“忽略”。
- “不用于这个项目的自动整理”阻止资产参与该项目后续自动组对；“本次不显示”仅修改 Comparison.visible。
- 删除／拆分自动组保留其稳定资产组合的抑制记录，素材版本更新也不使旧错误组合复活。
- 排除尚未建立 Asset 的候选时保留来源观察记录；重新绑定根或改名时应迁移对应决定。
- 新增另一候选导致原分组冲突时报告变化；不利用新候选绕过旧人工决定自动恢复整组。
- 用户可在“已排除／已忽略”中主动恢复自动建议；改变规则前预览影响，只作用于选择范围。
- 并行扫描与人工修改竞争时，以数据库中的最新决定为准；导入报告列明哪些结果因人工决定未应用。

## 11. Preset 与复制语义

- PresetVersion 保存初始 Block、内容条目和可选视觉建议；应用后实例属于文档，不实时继承方案修改。
- 创建或复制时，为 Document、Block、ContentModuleInstance、DeliveryItem、Comparison 分配新 ID，并重映射内部引用。
- 方案内部 ID 仅是复制时的模板引用键，不能成为多个项目共享的可变内容 ID。
- 默认方案不含真实客户资料、项目图片或客户交付链接；品牌默认值通过当前工作区配置解析。
- 方案可引用受允许的模板版本及同工作区品牌资源；缺依赖时明确提示并允许替换，不能静默丢模块。
- 重新应用方案展示将新增／替换／保留的内容，由用户明确选择范围；不建立隐式双向同步。
- 建议“复制为另一场婚礼”默认仅复制内容结构、通用文案和视觉，清空原客户、日期、客户交付链接和项目图片。
- 保留这些项目专属资料须明确选择复制范围；复制后的缺项按新项目检查，避免上一对新人资料被直接交付。
- 复制项目按所选复制范围新建项目和文档归属；保留素材时新建项目资产身份并重映射版本引用。
- 相同工作区内不可变字节可在底层共享，但新的可变 Asset 元数据、配对、排除状态均不能共享实例。
- 浏览器目录授权和历史导出不被冒充为新项目的当前结果；新项目需要单独验证来源绑定和交付资料。

## 12. 导出快照、修改竞争与删除

- “导出最新草稿”先等待当前编辑命令成功保存并取得 draftRevision 回执；未保存、失败或冲突时不能提交旧候选。应用用例控制此顺序，不能仅依赖 UI 的按钮状态。
- 正式预览先形成固定内容、日期和依赖的候选；用户提交时复核 draftRevision、资源版本及可用性。
- 候选仍有效才将其原样提交为不可变 ExportRevision；草稿已变或依赖失败时重新预检，不混用新旧值。
- 自动日期候选跨工作区日历日按 §4 重建；提交后编辑只影响下一次导出，次日重试也不重算日期。
- snapshot 固定公开展示值、章节顺序、布局、模板版本、日期、所用 AssetVersion 与派生图版本。
- 客户展示数据只包含实际可见字段；私有草稿、绝对路径、凭据不能因 JSON 被整体序列化而泄漏。
- snapshot 是历史事实；当前草稿仍只在数据库修改，不能同时编辑两个来源。
- 输出前根据固定版本验证字节，不按源路径重新读“最新版”；PDF 与长图的任务引用同一 revisionId。
- 素材依赖缺失时保留明确错误；可从匹配哈希的源重新取得，不能用同名不同内容补旧版本。
- 删除草稿中的 Asset／Comparison 不删除被 ExportRevision 引用的历史字节；先解除草稿引用再评估清理。
- 一个目标成功另一个失败属于部分完成；重试绑定原快照，修改内容后重做则产生新 revision。
- 文件记录提交与媒体写入不是一个天然原子事务；使用暂存、验证、提交和恢复检查，避免可用标记指向半文件。
- 备份需同时包含一致的数据库快照、被引用媒体、模板依赖和导出清单；缓存不必备份。

## 13. 租户与项目归属约束

- 所有应用用例取得 WorkspaceContext；本机固定上下文，云端来自已认证成员，不能直接相信请求里的 tenantId。
- Document 属于一个 Project；Block 属于一个 Document；条目与 Comparison 通过父 Block 推导归属。
- Comparison 仅允许引用同项目 Asset；品牌图允许同租户的品牌专用 Asset，不能因此开放所有跨项目资产。
- AssetVersion 必须属于引用中指定的 Asset；导出任务、缓存、产物与资源读取都继承相同归属范围。
- Preset／BrandProfile 属于工作区；系统可另提供只读内置 Preset，应用时仍复制为租户实例。
- 内置 TemplateDefinition／ContentModuleDefinition 是只读系统资源；工作室自定义版本属于租户。
- 系统定义不能引用客户数据；租户定义只能引用本租户可用资源，实例始终属于其文档。
- 跨项目复用素材经过显式复制或导入用例，不能让 UI 任意填写另一项目 ID 绕过关系约束。
- 云端迁移保留 ID 和版本关联，迁移必要文档用图并校验哈希；设备目录绑定保持设备专属。
- 多租户字段只是模型准备；认证、授权和实际存储隔离需在云端上线前单独完成验证。

## 15. 待用真实资料确定的默认值

- 客户展示字段、必填规则、文案类型、Preset 内容和是否需要单组布局覆盖。
- 实际目录里同一图片重复出现的频率，及用户对逻辑重复合并的偏好。
- 图片支持格式、文件体积／像素上限、扫描性能和历史资源保留策略。
- 自动识别完整组的默认审核提示强度；原则是不逐张强迫确认，也不掩盖冲突。
- 不变量可先确立，以上默认值需样本验证；当前阶段不把虚构场景当作已运行的验收测试。
