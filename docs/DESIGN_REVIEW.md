## 3. 需要统一的关键结论

| 发现的问题 | 采用的设计处理 | 用户可见效果 |
| --- | --- | --- |
| 正常结果也要求确认会抵消自动化价值 | 明确无冲突规则直接采用；只处理例外 | 不逐组点击通过 |
| 文案实例与章节都有显隐和排序 | DocumentBlock 管章节；条目管集合内部；文案实例不重复保存 | 切模板、隐藏后再显示不会出现两个答案 |
| 稳定 Asset ID 无法区分同名图片被覆盖 | 引入不可变 AssetVersion，草稿和导出固定版本 | 发现新图后可选择采用，旧交付保持原图 |
| 重扫可能重新建立用户拆开的误组 | 保存作用范围明确的人工排除／拆分决定 | 手工整理不会被自动化撤销 |
| 同一图片出现在多个位置可能误合并 | 存储去重与业务身份分开，来源不明时形成候选 | 不因相同哈希丢掉目录语义 |
| 没有对比图被误判为缺交付内容 | 按当前交付意图检查；已启用的空章节需明确处理 | 纯说明和交付清单也可正常输出 |
| 自动日期跨日或预览后继续编辑 | 候选记录修订与依赖，提交前检查；已提交版本不变 | 输出不混入未经对应预览的新内容 |
| 保存失败时数据库版本未变，可能误提交旧候选 | 导出最新草稿先等待当前编辑的保存回执，再校验候选 | 不把旧内容导出为貌似最新的文件 |
| “生成两种文件”可能掩盖其中一种失败 | 同一交付版本下分别记录目标任务 | 显示部分完成，并重试失败目标 |
| 所有目标预览就绪的门槛会扣住可用产物 | 共用输入有效时可明确先生成已就绪目标，保留其余目标阻塞记录 | 单个目标的问题不会让另一产物无故不可用 |
| 手机竖图难以同页清晰排放 | 提供受控跨页或换布局方案，保留同组标识 | 不静默缩小或裁掉画面 |
| 长图无法点击 URL | 为需要访问的交付资源设计二维码／取件说明等目标专用表达 | “只生成长图”仍有实际访问路径 |
| 浏览器不能把本地路径交给云端读取 | 浏览器授权扫描，只传索引和必要文档用图 | 不要求上传完整婚礼素材 |
| 本机随机端口可能使目录句柄不可见 | 稳定 loopback origin，授权失效有恢复提示 | 已导入文档用图仍可使用 |
| 模板预留被写成当前必须完成美术 | 区分本次结构设计与后续完整 MVP 模板验收 | 本次保持产品与架构设计范围 |

这些是经过审查的设计建议，尚未通过运行中的产品验证。

## 5. 设计推演与实现验收的区别

已经纳入文档的推演涵盖：正常交付、无对比、缺对、同目录冲突、跨目录同编号、重复导入、人工交换后重扫、拆组后重扫、同名新内容、改名、源目录失联、方案隔离、双输出版本一致和跨租户拒绝。

推演使用虚构姓名、文件名或对象 ID，仅检查规则之间是否一致；它不是运行结果。领域规格的输入／预期结果表、产品规格的代表场景和输出规格的验收表，都是后续可以落地的测试依据。

真正的应用完成需要另行取得：

- Windows 上可启动、保存、重开与导出的运行证据。
- 从真实或经允许的代表素材生成的 PDF／长图，包含三种输出模式。
- 缺对、重名、重扫、人工覆盖、并发修改、失联与中断的实际行为。
- 手机阅读、链接／二维码、字体、颜色、分页和发送渠道压缩后的检查结果。
- 云端功能上线前的身份、租户、对象存储与发布访问控制验证。

当前没有这些运行证据，也不因此声称应用已实现或可上线。
