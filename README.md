# Wedding Delivery Studio

Wedding Production OS 的第一阶段：帮助婚礼摄影师／摄像师组织交付内容、整理调色对比、选择视觉，并生成 PDF 或长图。

产品目标是让摄影师主要决定“交付什么、采用什么视觉、结果是否正确”，由系统承担可确定的整理、识别、匹配、排版和检查工作。

## 当前状态

当前为 **v0.3.0 本地可运行 MVP**：浏览器工作台 + 本机服务。支持项目管理、目录导入、调色对比、五套模板及真实 PDF／长图；新增个性化封面、制作详情／附录、对比说明与私人影像展册主设计。新增项目回收站、可恢复删除及章节拖拽排序，序言固定开头、署名固定结尾。详见 [v0.3.0 说明](docs/RELEASE_0_3_0.md)。

用户已确认：

- 工作平台为 Windows，当前项目资料保存在自己的电脑上。
- 客户主要在手机阅读交付内容。
- 后续需要通过浏览器登录和管理。
- 第一阶段专注 Delivery Studio；现有 Worker 页面保留用于未来适配。
- 设计阶段完成后，用户要求继续开发，并采用多子代理并行协作。

完整婚礼素材继续使用百度网盘；本版本不会上传到云端。Web 预告和短片未来接入用户自己的 S3，现有 Worker 未改动。当前没有云端登录、公开客户链接或 SaaS 服务，不能把本机服务直接暴露到公网。

## 启动

Windows x64：解压 `release/` 中的便携 ZIP，双击 `Start-Studio.cmd`，保持控制台窗口开启。运行时和导出所用 Chromium 随包提供，不要求另外安装开发工具。该包是跨平台组装的未签名预览版，**仍需 Windows 真机验收**；建议先用脱敏副本试做。

开发环境需要 Node.js 24 或更高版本：

```sh
npm ci
npx playwright install chromium
npm run build
npm start
```

浏览器访问 `http://127.0.0.1:4318`。已有可用 Chromium 时可以通过 `WDS_CHROMIUM_PATH` 指定路径；Linux 测试环境也支持 `/usr/bin/chromium`。UI 热更新另开终端运行 `npm run dev:ui`，本机服务用 `npm run dev`。

测试和打包：

```sh
npm test
npm run build
npm run test:e2e
npm run review:visual
npm run package:windows
```

`package:windows` 下载官方 Node／Chrome for Testing，并安装 Windows x64 原生依赖，需联网。首次生成 PDF／长图也会启动随包浏览器，但不会从网络下载项目资源或字体。

`review:visual` 使用虚构资料和带边框的横／竖测试图，调用正式渲染器生成五套模板的 PDF、长图、封面对照图和可直接打开的 `index.html`，保存到独立的 `release/visual-review/<时间>/`。样张不读取现有项目，不含真实照片；它用于排版核查，不能替代真实照片与手机显示效果确认。

## 第一次使用

1. 在工作室设置填写品牌和时区，创建项目、选一个可修改的方案。
2. 填新人信息和交付内容；添加百度网盘等稳定链接，或选择仅说明／线下交接。
3. 进入“素材与对比”，拖入或选择项目文件夹。默认只复制匹配规则或调色对比目录中的 JPEG／PNG，影片和其他文件仅记目录信息。
4. 检查导入报告；交换、补图、隐藏缺图组或手动建组。重新扫描同一目录请选择已有导入来源。
5. 在交付内容左侧拖动章节手柄调整中间章节顺序；序言和署名位置固定。选择模板、图片布局和输出方式，点击“检查并导出”。正式预览就绪后确认，下载文件再发送给客户。

项目卡片的“⋯”菜单提供复制、归档和删除。删除后进入回收站，可恢复至原分类；彻底删除会清除本机托管副本和历史产物，不会操作源目录、网盘或已另存的文件。回收站不会自动清空。

右侧手机框是快速预览，最终分页／分段以导出检查中的正式产物为准。过长内容、缺图、字体缺字等会明确提示，不会静默截断。

## 数据与备份

Windows 默认数据目录：`%LOCALAPPDATA%\WeddingDeliveryStudio`。直接源码启动时，Linux/macOS 默认为 `~/.local/share/wedding-delivery-studio`。用 `WDS_DATA_DIR` 可显式指定目录，`WDS_PORT` 可指定端口。

数据包括 SQLite、受管理的图片副本、预览快照和导出文件。**先退出 Studio，再备份整个数据目录**，不要只复制 SQLite 主文件。复制新版本程序不等于迁移或备份数据。导入不会修改、移动或删除源文件。

v0.3.0 会将工作区兼容标记升级为 3，以保护回收站状态与章节顺序；旧版本不能直接打开升级后的工作区。需要回退时恢复升级前的完整备份。

当前尚无自动备份、历史产物清理和加密存储；含客户资料的本地文件请使用 Windows 账户权限和磁盘加密保护。
